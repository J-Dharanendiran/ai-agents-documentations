# AI Agents: Understanding the Fundamentals

Let's build your understanding of AI Agents from the ground up, just like we did with RAG, Transformers, and the other concepts.

The goal is to understand not just *what* an AI Agent is, but why it exists, what problem it solves, how it works internally, and how all its components fit together.

## 1. First, what exactly is an AI Agent?

> Is it an LLM or a pipeline that we build like RAG?

**An AI Agent is a system that uses an LLM to make decisions and perform actions to accomplish a goal.**

It is neither a new type of LLM nor necessarily a fixed pipeline.

Imagine you ask an LLM:

**"Find the current weather in Chennai and tell me whether I should carry an umbrella."**

A normal LLM might respond using information it learned during training. But it doesn't necessarily know the current weather because its training data isn't continuously updated.

An AI Agent receiving the same request might:

1. Understand your request.
2. Decide that it needs current weather information.
3. Select a weather tool.
4. Call the weather API.
5. Receive the weather information.
6. Interpret the result.
7. Decide whether it needs another action.
8. Generate the final response.

The LLM didn't simply generate an answer. It **decided what to do, performed an action, observed the result, and used that result to decide what to do next.**

That's the fundamental idea behind AI Agents.

---

## 2. What is the relationship between an LLM and an Agent?

An LLM is the language model responsible for understanding and generating language.

An AI Agent is a larger system that uses an LLM as its decision-making component.

An agent generally contains these components:

| Component | Responsibility |
|---|---|
| LLM | Reasoning and decision-making |
| Tools | Performing external actions |
| Memory | Retaining relevant information |
| Planning | Breaking complex goals into smaller tasks |
| Execution loop | Repeatedly deciding and acting |
| Environment | The external world the agent interacts with |

Not every agent requires a separate memory module or sophisticated planning module. These are architectural capabilities that depend on the application.

**The LLM is the brain. The agent is the complete system built around it.**

For example, you can use GPT, Claude, Gemini, or even a locally running model through Ollama as the LLM inside an agent. The agent architecture is separate from the model itself.

---

## 3. Why do we even need AI Agents?

Remember the problem RAG solves?

An LLM has limitations:
- It doesn't necessarily know your private documents.
- Its knowledge can become outdated.
- It can hallucinate information.

RAG addresses this by connecting the LLM to an external knowledge source.

**User Query → Retrieval → Relevant Documents → LLM → Response**

But consider another problem. Suppose you want an AI system that:

1. Searches the internet for the latest AI research papers.
2. Reads the papers.
3. Compares their approaches.
4. Identifies their limitations.
5. Creates a comparison report.
6. Saves the report as a PDF.

A traditional RAG pipeline cannot do all this by itself. RAG can retrieve relevant information and provide it to an LLM. But the system also needs to decide which action to perform, choose the appropriate tool, execute it, inspect its output, decide what to do next, and continue until the task is complete.

This is where AI Agents become useful.

### RAG vs AI Agents

| RAG | AI Agent |
|---|---|
| Primarily retrieves information | Performs actions |
| Usually follows a predefined retrieval pipeline | Can dynamically choose actions |
| Retrieval is its central capability | Decision-making and action are central |
| Usually answers questions using external knowledge | Can accomplish multi-step tasks |

**RAG and AI Agents are not competing architectures. They can work together.**

An AI Agent can use a RAG system as one of its tools, alongside a web search tool, calculator, or database tool. The agent decides which tool to use depending on the task.

## 4. The most important concept: The Agent Loop

An AI Agent doesn't necessarily perform all its operations in one shot. Instead, it can operate in a loop, commonly called the **Agent Loop**.

### Example request

"Find the population of Chennai and calculate what 10% of that population is."

The agent needs to perform two operations.

**Step 1: Understand**

The LLM receives the request and identifies two requirements: find Chennai's population, and calculate 10% of that number.

**Step 2: Decide**

The LLM determines that it needs external information and decides to use a search tool.

**Step 3: Act**

The agent calls its search tool:

```python
search("Chennai population")
```

**Step 4: Observe**

The search tool returns information. Assume it returns a population figure of 10 million **for this hypothetical example**. The agent receives that result.

**Step 5: Decide again**

The LLM determines that it needs to calculate 10% and selects the calculator tool.

**Step 6: Act again**

```python
calculator(10000000 * 0.10)
```

**Step 7: Observe again**

The calculator returns `1000000`.

**Step 8: Final response**

The agent provides the result.

| Stage | What happens |
|---|---|
| Think | Understand what needs to be done |
| Act | Call an appropriate tool |
| Observe | Receive the tool's output |
| Think | Decide what to do next |
| Act | Perform the next action |
| Observe | Receive another result |
| Finish | Generate the final answer |

This cycle is the foundation of many agent architectures. The agent can repeat the loop until it decides the task is complete, reaches a stopping condition, or encounters a limit.

## 5. How does an LLM actually use tools?

An LLM fundamentally processes tokens and generates tokens. It cannot automatically execute Python code, access your database, or search the internet just because you ask it to.

Suppose we have a Python function:

```python
def calculator(expression):
    return eval(expression)
```

> **Safety note:** This illustrates the concept only. Never use unrestricted `eval()` on untrusted model-generated input in a real application. Use a safe arithmetic parser or a restricted calculator instead.

We want our LLM to use this function whenever it needs mathematical calculations. We provide the model with a tool definition. Conceptually:

```json
{
  "name": "calculator",
  "description": "Performs mathematical calculations",
  "parameters": {
    "expression": "string"
  }
}
```

Now the LLM knows a tool called `calculator` exists, what it does, and what input it expects.

When the user asks "What is 25 multiplied by 40?", the LLM might generate a structured tool call:

```json
{
  "name": "calculator",
  "arguments": {
    "expression": "25 * 40"
  }
}
```

**The LLM does not execute the Python function itself.**

Instead:

1. The LLM generates a tool-call request.
2. The agent framework or application receives it.
3. The application executes the corresponding Python function.
4. The function returns its result.
5. The result is sent back to the LLM.
6. The LLM generates the final response.

This is called **Tool Calling** or **Function Calling**. It's how an LLM can interact with the external world through an application.

## 6. Is an AI Agent a pipeline like RAG?

There are two broad architectural approaches worth distinguishing.

### A. Traditional workflow

You explicitly define the sequence of operations:

```text
User Input
    |
    v
Document Retrieval
    |
    v
LLM
    |
    v
Output
```

Every step is predetermined, similar to a traditional RAG pipeline.

### B. Agentic workflow

You provide the LLM with tools and allow it to decide which actions to take:

```text
       User Input
            |
            v
           LLM
            |
            v
      Select an Action
            |
            v
       Execute Tool
            |
            v
       Observe Result
            |
            v
           LLM
            |
       +----+----+
       |         |
    Continue   Finish
       |
       v
   Execute Next Tool
```

The execution path can change depending on the LLM's decisions and the results it receives.

Not every agent is completely autonomous. Developers can impose strict rules, predefined steps, tool restrictions, and execution limits.

---

## 7. AI Agent vs Agentic Workflow

These terms are related, but not identical.

**AI Agent:** A system where an LLM dynamically decides which actions to take based on the current situation.

**Agentic Workflow:** A workflow that incorporates agent-like capabilities, such as LLM-based decisions, tool usage, or iterative reasoning.

For example, a predefined workflow might always:

1. Search the web.
2. Summarize the results.
3. Generate a report.

An agent might instead:

1. Decide whether web search is necessary.
2. Choose which search queries to execute.
3. Evaluate the results.
4. Search again if the information is insufficient.
5. Decide when it has enough information.

The distinction is primarily about how much decision-making happens dynamically.
